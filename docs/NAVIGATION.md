# 내비게이션 (자동 길찾기)

`walkTo` / `runTo` / `sitDown`은 가구·벽·서 있는 인물을 알아서 피해 간다. 구현은 `packages/core/src/nav.ts`(헤드리스·순수·결정론)이고, 컴파일(`compile`)이 액션을 키로 풀 때 호출한다.

## 조사 요약

| 방식 | 대표 | 특징 | Blockshot에서의 판단 |
| --- | --- | --- | --- |
| **내비메시(Recast/Detour)** | Unity NavMesh, Unreal, [recast-navigation-js](https://npmjs.com/package/recast-navigation)(WASM, three.js 연동) | 지오메트리를 복셀화 → 걸을 수 있는 영역 → 볼록 폴리곤. 에이전트 반경·높이·경사·계단 높이를 베이크 시점에 반영. 쿼리는 폴리곤 A* + 깔때기(funnel) 알고리즘으로 코너만 남김 ([Recast 문서](https://recastnav.com/md_Docs_2__1__Introduction.html)) | 경사·다층이 필요할 때 적합. 프리비즈의 평평한 바닥 한 장에는 과함. WASM 의존은 core의 "DOM/three 금지·순수 TS" 규칙과 결정론 테스트에 불리 |
| **three-pathfinding** | [three-pathfinding](https://npmjs.com/package/three-pathfinding)(PatrolJS 기반) | 미리 만든 내비메시(Blender/Recast)를 받아 A* + funnel. 내비메시를 **만들어 주지는 않음** | 메시 생성기가 없어 부족 |
| **격자(occupancy grid) + A\*** | 2D/탑다운 게임, 로봇 | 베이크 = 셀 래스터라이즈, 장애물을 에이전트 반경만큼 부풀림. 구현·디버깅이 단순, 결정론적. 경로가 8방향으로 꺾이므로 후처리 필요 | **채택** |
| **Any-angle (Theta\*, string-pulling)** | 격자 위 후처리 | 시야선(line of sight)이 트이면 중간 점을 건너뛰어 직선 구간만 남김 | **채택** (A* 결과에 시야선 평활) |

선택 근거: ① 장면은 평평한 한 층, 크기 ≤ 수십 m, 장애물은 회전한 직사각형 위주 → 격자로 충분. ② core는 순수 TS·결정론이어야 함(같은 spec이면 같은 경로, 힙 동점은 인덱스로 결정). ③ 디버깅/시각화(탑뷰 오버레이)가 쉬움. 다층·경사·복잡한 지오메트리(GLB 지형)가 필요해지면 `NavGrid` 자리에 Recast 베이크를 꽂는 구조로 확장한다(인터페이스: `bakeNav` / `findPath` / `routeLegs`).

## 베이크 (`bakeNav`)

- **범위**: 방 = 벽 바깥 3 m까지(문 밖으로 나가는 동작용). 열린 공간/거리 = 인물·소품·걷기 목적지의 경계 + 5 m (공간 크기로 제한). 셀 크기 0.1 m, 한 변 420칸을 넘으면 자동으로 키움.
- **막히는 곳**: ① 바닥에 놓인 비-장식 소품(`passable`이 아니고 y ≤ 0.3 m)의 회전한 직사각형 + **몸 반경**, ② 방 벽(안쪽으로 반경 + 두께), ③ 창문 쪽 벽. **문(door) 구간은 열려** 있고 문 밖 2.5 m 현관 앞까지 걸을 수 있다.
- **몸 반경**: 평균 체형 0.22 m, 키·체형에 비례(0.15~0.45 m). 반경별로 격자를 하나씩 캐시.
- **고정 물체 vs 이동 물체**
  - 고정(베이크됨): 소품, 벽.
  - 인물은 **걷기/달리기/앉기/일어서기 액션이나 위치 트랙이 없으면 "고정 인물"** → 다른 인물의 길찾기에서 장애물(원). 움직이는 인물은 장애물로 치지 않는다(시간에 따라 위치가 달라 정적 격자로는 못 푼다 — 아래 한계).

## 쿼리

- `findPath(grid, from, to, avoid)`: 8방향 A*(대각선은 모서리를 스치지 않을 때만), 휴리스틱 octile, 동점은 셀 인덱스 → 같은 입력 = 같은 경로. 결과는 시야선 평활(string-pulling)로 직선 몇 개로 줄인다.
- 출발점이 가구에 바짝 붙어 부풀린 영역 안이면 가장 가까운 빈 곳으로 옮겨 시작. **목적지가 소품 안**(예: "테이블로 걸어간다" → 테이블 중심)이면 가장 가까운 빈 곳(테이블 옆)에서 멈춘다(`snappedGoal`).
- `routeLegs(grid, points, avoid)`: **손으로 쓴 경로는 존중**한다. 구간마다 직선이 비어 있으면 그대로 두고, 막힌 구간만 A* 경로로 바꾼다. 경로가 없으면(완전히 막힘) 원래 점을 두고 `unreachable`로 표시 → `lintLayout`이 "갈 수 있는 길이 없다"고 경고.

## 액션과의 연결

- `walkTo` / `runTo`: 기본 자동 길찾기. `"direct": true`면 그대로 직선(의도적으로 통과시킬 때). 시간(speed/duration)은 **우회한 경로 길이** 기준으로 배분되고, 각 구간에서 진행 방향을 바라본 뒤 다음 구간 시작 0.3초 안에 꺾는다.
- `sitDown`: 좌석 앞 0.5 m 지점까지 길찾기(좌석 자체와 다른 가구를 피해 의자 옆으로 돌아감) → 서서 → 굽히며 뒷걸음으로 착석.
- `compile()`이 `scene.routes`(액션 → 실제로 걷는 점들)와 `scene.unreachable`을 채운다. 탑뷰는 이것으로 경로를 그린다(우회한 경로는 연두색).

## 탑뷰 "내비 베이크" 오버레이

탑뷰 왼쪽 위 **내비 베이크** 버튼: 막힌 셀(가구+몸 반경)을 붉게, 벽을 회색으로, 고정 인물은 빨간 원, 움직이는 인물은 파란 점선 원으로 보여 준다. 걷기 경로는 이 격자 위에서 계산된 결과다.

## 한계 / 다음 단계

- 움직이는 인물끼리의 충돌 회피는 없다(시공간 A* 또는 RVO/ORCA 같은 군중 회피가 필요). 지금은 겹쳐 걷지 않게 `lookAt`/타이밍으로 연출한다.
- 몸이 통과할 수 없는 틈(반경×2보다 좁은 길)은 막힌 것으로 본다 — 문 폭은 0.5 m 이상(몸 반경 0.22 기준)이어야 지나간다.
- 소품이 y > 0.3 m에 떠 있거나(선반 등) 높이에 따른 통과(몸을 숙여 지나가기)는 다루지 않는다.
- 다층/경사/GLB 지형: Recast 계열 내비메시로 교체(위 표 참고).
